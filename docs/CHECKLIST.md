# Чеклист приёмки перед релизом

Статусы честные: «проверено» ставится только там, где проверка реально выполнена
и её можно повторить командой. «На стенде» — то, что проверяется только на хостинге.

Повторить все проверки:

```bash
php app/bin/build.php                      # сборка
node tools/check.mjs                       # ссылки, картинки, canonical, H1, метатеги, карты сайта, микроразметка
node tools/make-seo.mjs                    # карта редиректов + покрытие и цепочки
node tools/serve.mjs 8098 &                # сервер для браузерных проверок
node tools/shots.mjs                       # вёрстка и горизонтальный выезд на 360/768/1280/1920
node tools/check-search.mjs                # поиск по номеру чертежа, 16 написаний
node tools/check-forms.mjs                 # формы заявок: типы, поля, кнопки
node tools/check-redirects.mjs <адрес>     # редиректы на живом сервере, включая http/www-варианты
node tools/check-admin.mjs <пароль>        # круговой тест админки со сверкой всех файлов данных
node tools/check-admin-add.mjs <пароль>    # добавление новости, статьи и позиции каталога через формы
php  tools/check-mime.php                  # типы файлов, которые принимает форма «прислать чертёж»
php  tools/check-mail.php                  # сборка письма с вложениями
php  app/bin/deploy.php list               # что поедет как код, а что считается контентом
```

## Не проверено, нужен сервер

| | Пункт | Почему |
|---|---|---|
| ⬜ | **Полный цикл заливки по FTP: init → правка на сервере → push → pull** | проверен отбор файлов (`deploy.php list`) и логика охранных проверок в коде — то, что переписывали под этот проект. Сам обмен по FTP достался из проверенного проекта без изменений, но на эмуляторе FTP здесь не прогонялся. Перед первым релизом прогнать на реальном хостинге: после `init` создать позицию в админке и загрузить фото, затем `push` и `pull` — и позиция, и фото должны уцелеть |
| ⬜ | Реальная отправка письма | `mail()` на Windows не отправляет; проверена только сборка письма. На хостинге отправить проверочную заявку кнопкой в админке |

## Делается на стенде и после релиза

| | Пункт | Что сделать |
|---|---|---|
| ⬜ | **Каждое правило из `redirects.csv` даёт ровно один 301 и затем 200** | обязательно **до** релиза: поднять стенд и прогнать `node tools/check-redirects.mjs https://стенд`. Ни PHP-роутер, ни сборщик `.htaccess` не исполняют — правила нигде ещё не отрабатывали под Apache. Скрипт проверяет и варианты хоста (http, www, http+www) на 15 адресах: именно там у старого сайта была цепочка из трёх переходов с уходом на http |
| ⬜ | Как хостинг сообщает о HTTPS | проверить, какую переменную отдаёт его nginx (`HTTPS` или `X-Forwarded-Proto`). Неверное определение даёт бесконечный редирект — возможно, именно это и было «циклическим редиректом» на старом сайте |

## Что ещё не сделано и почему

| Пункт | Состояние |
|---|---|
| **Описания назначения деталей** | написаны по 20 шаблонам, подобранным по типу детали: у «плиты дробящей» один текст, у «брони» другой и так далее. Это лучше пустоты и лучше, чем у конкурентов, но **уникальным текстом для каждой из 560 позиций это не является**. Уникализировать имеет смысл в первую очередь у ходовых позиций — плит, броней, подпятников |
| **ТТХ машин** | не выдуманы: блок на страницах моделей не выводится, пока заказчик не пришлёт характеристики |
| **Взрыв-схемы узлов** | не сделаны: нужны чертежи или схемы узлов от заказчика. Вместо них работает группировка деталей по узлам на странице модели |
| **Фотографии деталей** | 100 позиций из 560 с настоящими фото (в основном сканы чертежей), у остальных аккуратная заглушка «Нужно фото детали» |
| **Региональные страницы** | сознательно не делались: страница города без уникального смысла получает фильтр за переспам. Заложено указание географии поставок на `/delivery/` |

## Что проверить именно на этом хостинге

Текущий сервер отдаёт `X-Powered-By: PHP/5.6.40`. Нужен PHP 8.1+.
Отдельно проверить: применился ли `.user.ini`, реальный ли `REMOTE_ADDR`,
работает ли `mail()` с адресом на домене, доступен ли `api.telegram.org`,
доходит ли rewrite `/admin/…` до `admin/index.php`, разрешён ли `Options -Indexes`
(иначе будет 500). Сразу после `deploy init` открыть главную и секретный адрес входа.
