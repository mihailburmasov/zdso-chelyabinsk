# masterskie174.ru — Завод дробильно-сортировочного оборудования (ЗДСО), Челябинск

Редизайн действующего сайта с сохранением домена и поискового веса.
Вариант C: контент в `data/*.json`, PHP-сборщик делает статический HTML,
самописная админка правит JSON формами и сразу пересобирает сайт.

- 644 страницы, из них 560 карточек деталей с номерами чертежей
- 747 старых адресов разобраны: 584 сохраняют адрес, 161 получают один 301, 2 остаются 404 (служебные Битрикса)
- Поиск находит деталь по номеру чертежа в любом написании
- Twitter и Facebook удалены полностью, добавлены MAX, Telegram и WhatsApp

Подробности аудита старого сайта — в [docs/AUDIT.md](docs/AUDIT.md).
Что нужно получить от заказчика — в [docs/CLIENT-REQUESTS.md](docs/CLIENT-REQUESTS.md).
Чеклист перед релизом — в [docs/CHECKLIST.md](docs/CHECKLIST.md).

## Как это работает

```
data/*.json  ──►  php app/bin/build.php  ──►  dist/ (готовый сайт)
     ▲                                             │
     │                                             ▼
админка (PHP) ◄── правки клиента            посетитель
```

`data/` — единственный источник правды. HTML руками не правится: он пересобирается
при каждом сохранении в админке (полная сборка 644 страниц занимает около секунды).
Если сборка упала, файлы возвращаются как были и сайт остаётся рабочим.

## Ветки репозитория

- **`main`** — реальный деливерабл: пути от корня домена, как для боевого хостинга.
  Именно эту ветку разворачивают у клиента (`php app/bin/deploy.php init`).
- **`gh-pages`** — только демо для показа: https://mihailburmasov.github.io/zdso-chelyabinsk/
  Руками её не правят: она собирается из `main`.

**Автосборка демо пока не подключена.** Файл `.github/workflows/deploy-pages.yml`
лежит в рабочей копии, но не в репозитории: у токена `gh` нет права `workflow`,
и GitHub отклоняет пуш файлов из `.github/workflows/`. Чтобы включить автосборку,
один раз выдайте это право и запушьте файл:

```bash
gh auth refresh -h github.com -s workflow
git add .github && git commit -m "Автосборка демо на GitHub Pages" && git push
```

До этого демо обновляется вручную — командой из блока ниже, после чего содержимое
`OUT_DIR` пушится в ветку `gh-pages`.

**Что в демо не работает и почему.** GitHub Pages — статический хостинг без PHP,
поэтому там не работают форма заявки (`lead.php`), обработчик 404 и правила
`.htaccess`: редиректы со старых адресов на Pages не отрабатывают. Проверять их
нужно на стенде хостинга: `node tools/check-redirects.mjs <адрес>`.

**Демо закрыто от индексации** — собирается с `STAGING=1`: `robots.txt` отдаёт
`Disallow: /`, на каждой странице `noindex, nofollow`. Это принципиально: сайт
переносит накопленный поисковый вес, и проиндексированная копия на домене
github.io создала бы дубли ровно тогда, когда их быть не должно.

Собрать демо локально (в Git Bash нужен `MSYS_NO_PATHCONV=1`, иначе путь
превратится в windows-путь):

```bash
MSYS_NO_PATHCONV=1 SITE_URL=https://mihailburmasov.github.io   SITE_BASE=/zdso-chelyabinsk OUT_DIR=/tmp/pages-build STAGING=1   php app/bin/build.php
```

## Локальная работа

Нужны PHP 8.1+ (с gd, mbstring, fileinfo, exif, curl) и Node 18+.

```bash
php app/bin/build.php                     # собрать сайт в dist/
php -S 127.0.0.1:8080 app/dev-router.php  # сайт + админка + приём заявок
node tools/serve.mjs 8098                 # только dist/, многопоточно (для скриншотов)
```

Для админки на своём компьютере создайте `app/config.local.php`:

```php
<?php
return [
    'site_url' => 'http://127.0.0.1:8080',
    'base_path' => '',
    'admin_local_no_gate' => true,  // вход без секретного адреса
];
```

и задайте пароль: `php app/bin/admin-setup.php <пароль>`.
**`app/config.local.php` на сервер не заливается** — у сервера свой `config.server.php`.

## Скрипты в tools/

| Скрипт | Что делает |
|---|---|
| `make-data.mjs` | **разовый импорт** `data/catalog/*` из данных обхода старого сайта (`seo/_audit/`). Переносит уже отредактированные поля по совпадению адреса, но **удаляет и пересоздаёт файлы разделов**: позиции, добавленные менеджером через админку, пропадут. После запуска сайта не запускать |
| `seed-copy.mjs` | заполняет пустые тексты разделов и описания назначения деталей; идемпотентный |
| `make-price.mjs` | собирает `data/price.json` из прайса старого сайта |
| `make-photos.mjs` | пересобирает медиатеку `data/photos.json` по файлам в `public/upload/` |
| `make-webp.php` | делает `<путь>.webp` рядом с используемыми фотографиями; исходный файл остаётся на месте, поэтому старые адреса картинок не ломаются |
| `check.mjs` | ссылки, картинки, canonical, H1, title, description, карты сайта, микроразметка, следы соцсетей |
| `check-search.mjs` | поиск по номеру чертежа в настоящем браузере, 16 написаний |
| `check-forms.mjs` | формы заявок: тип, поля, надписи на кнопках |
| `check-redirects.mjs` | карта редиректов на живом сервере: один 301 → 200, без цепочек |
| `check-redirects.mjs` (продолжение) | и варианты хоста: http, www, http+www — там, где у старого сайта была цепочка |
| `check-admin.mjs` | круговой тест админки: загрузить и сохранить каждую форму, затем сверить все файлы данных со снимком |
| `check-mime.php` | какие MIME-типы определяет этот сервер для PDF, DWG, DXF, JPG, XLSX, ZIP и отсекаются ли .php и .html |
| `check-mail.php` | сборка письма с вложениями без почтового сервера: текст, файлы, лимит размера |
| `make-seo.mjs` | карта редиректов, `public/.htaccess`, `seo/*.csv` + проверка покрытия и цепочек |
| `make-semantics.mjs` | черновое семантическое ядро |
| `make-icons.php` | favicon, apple-touch-icon, og-картинка |
| `shots.mjs` | скриншоты и проверка горизонтального выезда на 360/768/1280/1920 |
| `serve.mjs` | статический сервер для `dist/` |

Порядок при полной пересборке данных (только до запуска сайта):
`make-data` → `seed-copy` → `make-photos` → `make-webp` → `php app/bin/build.php` → `make-seo` → `make-semantics` → `check`.

После запуска контент правится только через админку. Из скриптов остаются безопасными
`make-photos`, `make-webp`, `make-seo`, `make-semantics` и все `check-*`.

## Заливка на хостинг

1. Создайте `app/config.server.php` по образцу `app/config.server.example.php`:
   корень сайта на хостинге — `public_html`, в нём лежит статика и две заглушки
   (`admin/index.php`, `lead.php`), а `app/`, `data/` и `storage/` лежат рядом, вне корня.
2. Создайте `app/deploy.local.php` по образцу `app/deploy.example.php` (доступ к FTP).
3. `php app/bin/deploy.php list` — покажет, что поедет как код, а что считается контентом.
   Проверьте, что в коде нет `upload/media` (это фото клиента), а в контенте есть `data/catalog/`.
4. `php app/bin/deploy.php init <пароль>` — зальёт код и напечатает секретный адрес входа.
5. Дальше: `php app/bin/deploy.php push` (код сюда → на сервер) и
   `php app/bin/deploy.php pull` (контент с сервера → сюда). Перед правкой шаблонов — всегда `pull`.

**Перед первым `pull`** сделайте `git init` и коммит: `pull` перезаписывает `data/`
и `public/upload/media`, и без репозитория откатиться будет нечем — скрипт на это ругается.

**Фотографии со старого сайта удалять через медиатеку нельзя:** файлы в `upload/iblock`,
`upload/medialibrary` и `upload/resize_cache` считаются кодом, поэтому следующий `push`
зальёт их обратно. Если такое фото нужно убрать с сайта — уберите его из карточек,
а файл оставьте: по старому адресу он всё ещё может приходить из поиска по картинкам.

**Разделение кода и контента.** Код — `app/`, статика `public/` и 913 файлов
старых фотографий в `upload/iblock`, `upload/medialibrary`, `upload/resize_cache`
(их делаем мы, клиент их не меняет). Контент — все `data/**.json` и `public/upload/media/`,
куда админка кладёт загруженные клиентом фото: оттуда они едут только `pull`, а `push` их не трогает.

**Требование к хостингу:** PHP 8.1 или новее. На текущем сервере сайта стоит PHP 5.6 —
версию нужно переключить в панели хостинга до релиза, иначе админка не запустится.

## Что проверить на реальном хостинге

Эмуляция этого не покажет: версия PHP у веб-сервера, применился ли `.user.ini`,
реальный ли `REMOTE_ADDR`, работает ли `mail()` с адресом на домене, доступен ли
`api.telegram.org`, доходит ли rewrite `/admin/…` до `admin/index.php`,
разрешён ли `Options -Indexes`. После `init` сразу откройте главную и адрес входа.
